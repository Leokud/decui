Концепции и архитектура DECUI

Добро пожаловать в пошаговый интерактивный учебник по DECUI — декларативному Python-фреймворку для разработки настольных бизнес-приложений и ERP-систем.

Как устроен поток данных в DECUI
Python-класс метаданных
(поля, строки, действия)
➔
SQLAlchemy ORM
(генерация моделей на лету)
➔
SQLite База данных
(авто-миграции)
➔
PySide6 GUI
(AutoForm, ListView, Reports)

Зачем нужен специализированный фреймворк?

В учетных системах обычного простого CRUD недостаточно. Здесь требуется:

  • Разделение на справочники и транзакции: товары и контрагенты хранятся как справочники (Master Data), а чеки, счета и накладные — как документы, привязанные к календарному моменту.
  • Проведение документов: пока документ черновик — остатки не меняются. При проведении он формирует записи в регистрах (движения). При отмене проведения — движения удаляются.
  • Спецификации строк (Master-Detail): заказ всегда состоит из шапки (клиент, дата) и строк (товар, количество, цена).
  • Автоматический расчет остатков: вместо медленного пересчета миллионов строк история собирается в регистры накопления.

Сопоставление терминов: Python/ERP vs 1С

DECUI поддерживает оба стиля именования. Вы можете использовать тот словарь терминов, который удобен именно вам:

Общепринятый ERP/Бэкенд Термин 1С Классы DECUI Назначение
Master Data / Lookup Справочник MasterData, Catalog Условно-постоянные сущности (товары, клиенты)
Transaction / Document Документ Transaction, Document Хозяйственные операции с датой и номером
Line Items / Child Table Табличная часть @line_items, @tab_part Строки спецификаций внутри документа
Form Action Команда @action, @command Кнопки действий на форме с бизнес-логикой
Balance Ledger Регистр накопления @ledger, @accumulation Хранилище остатков и оборотов (склад, деньги)
Value History Регистр сведений @history_register, @information Периодические значения (курсы валют, прайс)
Ledger Entry Движение LedgerEntry, Movement Единичная запись баланса (+приход, -расход)

from decui import ERPApplication, MasterData, String, Decimal as D, master_data

@master_data
class Product(MasterData):
    __verbose_name__ = "Товары"
    __section__      = "Склад"

    name  = String("Наименование", required=True)
    price = D("Цена", precision=10, scale=2, min_value=0)

if __name__ == "__main__":
    app = ERPApplication(title="Учет товаров", db_path="warehouse.db")
    app.run()

    app = ERPApplication(title="Учет товаров", db_path="warehouse.db")

Практический пример: Категории и Товары с автонумерацией

from decui import master_data, MasterData, String, Decimal as D, Ref

@master_data
class Category(MasterData):
    __verbose_name__ = "Категории"
    __section__      = "Склад/Справочники"

    title = String("Название категории", required=True)

@master_data
class Product(MasterData):
    __verbose_name__ = "Товары"
    __section__      = "Склад/Справочники"
    # Автонумерация: PRD-000001, PRD-000002...
    __numbering__    = {"prefix": "PRD", "pattern": "{prefix}-{seq:06d}"}

    code     = String("Артикул", read_only=True)
    name     = String("Наименование", required=True)
    category = Ref(Category, "Категория", representation_field="title")
    price    = D("Цена закупки", precision=10, scale=2, min_value=0)
💡 Как работает Ref(..., representation_field="title")?
Фреймворк превратит это поле в выпадающий список (комбобокс), подгрузит доступные категории из базы данных и будет показывать значение поля title вместо непонятного числового ID.

Документы и спецификации строк (@line_items)

Документ отражает факт хозяйственной операции (счет, приходная накладная, чек продажи). В отличие от справочника, он имеет дату, статус проведения и табличную часть со строками.

Создание документа «Заказ покупателя»

from decimal import Decimal
from decui import transaction, Transaction, String, Integer, Decimal as D, Ref, line_items, action

@transaction
class SaleOrder(Transaction):
    __verbose_name__ = "Заказы клиентов"
    __section__      = "Продажи"
    # Шаблон: ORD-2026-000001
    __numbering__    = {"prefix": "ORD", "pattern": "{prefix}-{year}-{seq:06d}"}

    customer = String("Клиент", required=True)
    total    = D("Итоговая сумма", precision=10, scale=2, read_only=True, default=Decimal("0.00"))

    # Табличная часть со строками товаров
    @line_items
    class Items:
        product  = Ref(Product, "Товар", representation_field="name")
        quantity = Integer("Кол-во", default=1, min_value=1)
        price    = D("Цена продажи", precision=10, scale=2)
        amount   = D("Сумма", precision=10, scale=2, read_only=True)

    # Кнопка действия на форме заказа
    @action("Рассчитать сумму")
    def calculate_total(self):
        tot = Decimal("0.00")
        for row in self._table_data.get("Items", []):
            qty = Decimal(str(row.get("quantity", 1)))
            prc = Decimal(str(row.get("price", 0)))
            row["amount"] = qty * prc
            tot += row["amount"]
        self.total = tot
Автоматический расчет строк в UI
Если в табличной части используются стандартные имена price, quantity и amount, встроенный виджет таблицы DECUI автоматически умножает количество на цену при вводе прямо в интерфейсе!

Как описывать бизнес-логику и проверки (Валидация, @action, Исключения)

Бизнес-логика в DECUI пишется на чистом Python прямо в методах сущности. Достаточно добавить декоратор @action("Текст кнопки"):

import datetime
from decui import transaction, Transaction, String, DateTime, action

@transaction
class TaskOrder(Transaction):
    title = String("Задача", required=True)
    deadline = DateTime("Дедлайн", default=datetime.datetime.now)
    status = String("Статус", default="В работе")

    # 1. Валидация и проверка бизнес-правил
    @action("Завершить задачу")
    def complete(self):
        # Если правило нарушено, вызываем ValueError:
        # DECUI автоматически перехватит ошибку, отменит сохранение
        # и покажет красивое диалоговое окно пользователю!
        if self.status == "Завершена":
            raise ValueError("Задача уже завершена ранее!")
            
        self.status = "Завершена"

    # 2. Арифметика дат и времени в логике
    @action("Продлить на 3 дня")
    def extend_deadline(self):
        current = self.deadline or datetime.datetime.now()
        # Стандартная работа с datetime и timedelta в Python
        self.deadline = current + datetime.timedelta(days=3)
Жизненный цикл выполнения действия (@action):
  1. Пользователь нажимает кнопку на форме.
  2. DECUI считывает введённые значения из всех полей и табличных частей в объект self.
  3. Выполняется ваш Python-метод. Если возникнет ValueError, сохранение отменяется, а пользователю показывается текст ошибки.
  4. При успешном завершении объект автоматически сохраняется в базу данных (db.save(self)).
  5. Форма немедленно обновляет экранные виджеты новыми значениями.
Шаг 4 из 8

Складской учёт и регистры остатков (@ledger)

Сердце любой системы учета — Регистры остатков (Ledgers). Они работают по принципу Event Sourcing: документы формируют записи изменений (приход +, расход -), а регистр мгновенно отдает актуальный баланс.

1. Определение складского регистра

from decui import ledger, Ledger, Dimension, Metric

@ledger
class StockLedger(Ledger):
    warehouse = Dimension("Склад")    # Разрез аналитики
    product   = Dimension("Товар")    # Разрез аналитики
    quantity  = Metric("Количество")  # Ресурс (число)

2. Генерация движений при проведении заказа

Добавим в документ метод get_ledger_entries(). Когда пользователь нажмет «Провести и закрыть», DECUI автоматически запишет расход со склада:

from decui import LedgerEntry

@transaction
class SaleOrder(Transaction):
    ...
    # Метод формирования движений при проведении
    def get_ledger_entries(self):
        entries = []
        for row in self._table_data.get("Items", []):
            entries.append(LedgerEntry(
                register=StockLedger,
                dimensions={"warehouse": "Основной", "product": row["product"]},
                resources={"quantity": row["quantity"]},
                is_income=False,  # False = расход со склада (-qty)
            ))
        return entries

3. Запрос остатков товаров

from decui import get_ledger_balance

# Запрос текущих остатков на Основном складе с группировкой по товарам:
stocks = get_ledger_balance(db, StockLedger, warehouse="Основной", group_by=["product"])

for s in stocks:
    print(f"Товар #{s['product']}: остаток {s['quantity']} шт.")
Шаг 5 из 8

Периодические значения (@history_register)

Часто требуется хранить величины, меняющиеся во времени: курсы валют на дату, историю цен поставщиков, тарифы сотрудников.

Регистр сведений: Курсы валют

from decimal import Decimal
from decui import history_register, HistoryRegister, Dimension, Resource, set_record, get_latest, get_records

@history_register
class CurrencyRate(HistoryRegister):
    currency = Dimension("Валюта")
    rate     = Resource("Курс к рублю", field_type=Decimal)

# Добавление курсов:
set_record(db, CurrencyRate, dimensions={"currency": "USD"}, resources={"rate": Decimal("92.50")})
set_record(db, CurrencyRate, dimensions={"currency": "EUR"}, resources={"rate": Decimal("100.20")})

# Получение самого последнего курса валюты (срез последних):
usd = get_latest(db, CurrencyRate, currency="USD")
print(f"Текущий курс доллара: {usd['rate']}")

# Получение всей истории изменений:
history = get_records(db, CurrencyRate, currency="USD", order_by="id", desc=True)
Шаг 6 из 8

Аналитические отчёты и диаграммы (@report)

DECUI строит параметрические отчеты: вы объявляете колонки таблицы, параметры формы фильтрации и метод выборки данных.

Отчет по продажам с агрегацией сумм

from datetime import date
from decui import report, QueryReport, Column, DateParam, StringParam

@report
class SalesReport(QueryReport):
    title = "Сводка продаж за период"
    
    # Колонки таблицы с автоматическим суммированием итога
    columns = [
        Column("Дата", "date", width=120),
        Column("Клиент", "customer", width=200),
        Column("Сумма", "total", width=140, align="right", aggregate="sum", suffix=" руб."),
    ]

    # Параметры фильтрации на форме
    date_from = DateParam("Дата с", required=True, default=date.today)
    date_to   = DateParam("Дата по", required=True, default=date.today)
    customer  = StringParam("Фильтр по клиенту")

    def execute(self, db, date_from, date_to, customer=None, **kwargs):
        orders = db.list(SaleOrder)
        results = []
        for o in orders:
            # Отбираем только проведенные документы
            if not o.is_posted:
                continue
            if customer and customer.lower() not in (o.customer or "").lower():
                continue
            results.append({
                "date": str(o.date.strftime("%d.%m.%Y")),
                "customer": o.customer,
                "total": str(o.total or 0),
            })
        return results
🎨 Цветовая и визуальная индикация строк
Каждая строка отчёта может содержать специальные ключи форматирования:
  • "_style": "completed" или "_strikeout": True — зачёркнутый серый шрифт (для выполненных задач или завершённых этапов).
  • "_style": "current" или "_bold": True — полужирный шрифт (для текущего активного этапа).
  • "_color": "#2563eb" — произвольный цвет текста ячеек.
📊 Встроенный виджет диаграмм: BarChart
Вы можете выводить горизонтальные и вертикальные столбчатые графики с помощью виджета decui.ui.chart.BarChart: 
from decui.ui.chart import BarChart
chart = BarChart(labels=["USD", "EUR", "CNY"], values=[92.5, 100.2, 12.8], title="Курсы")
layout.addWidget(chart)
Шаг 7 из 8

Сборка в автономный .exe для распространения

Вашим пользователям не нужен установленный Python или терминал. PyInstaller упакует всё приложение в единый исполняемый файл.

1. Скрипт сборщика (build_exe.py)

В корень репозитория включен готовый настроенный скрипт сборки:

python build_exe.py

2. Что происходит во время сборки?

  • Автоматически очищаются временные файлы сборки и тестовые базы данных.
  • Подтягиваются все необходимые динамические библиотеки Qt (PySide6) и SQLAlchemy.
  • Включаются флаги --onefile (один бинарник) и --windowed (без черного окна консоли).
  • Результат помещается в папку dist/ERP.exe (на Windows) или dist/ERP (на Linux).

3. Автоматическая миграция схемы базы

🔄 Контроль версий структуры
DECUI вычисляет MD5-хеш метаданных всех классов. Если вы добавите новое поле в код и запустите обновленный .exe, фреймворк обнаружит изменение схемы и выполнит чистый апгрейд таблиц.
Шаг 8 из 8

CLI-утилита и современный Developer Experience (DX)

Как писать меньше шаблонного кода, ускорить разработку и легко тестировать приложения.

1. Консольная утилита decui

DECUI включает удобный интерфейс командной строки для генерации проектов, запуска и тестирования:

# Создать готовый проект со справочниками, документами и отчетами
decui new my_erp
cd my_erp

# Запустить приложение (автоматически находит app.py)
decui run

# Запустить тесты (автоматически настраивает offscreen-режим для GUI)
decui test

# Собрать приложение в автономный бинарник
decui build

2. Авто-вывод названий полей (Auto-naming)

Вам больше не нужно повторять имена в дескрипторах. Первый аргумент display_name теперь опционален:

# Раньше:
name = String("Наименование", required=True)
unit_price = Decimal("Unit price", scale=2)

# Теперь — чисто и лаконично:
name = String(required=True)                  # Авто-подпись: "Name"
unit_price = Decimal(scale=2, currency="RUB") # Авто-подпись: "Unit price"
customer = Ref(Customer, required=True)       # Авто-подпись: "Customer"
is_active = Boolean(default=True)             # Авто-подпись: "Is active"

3. Умные спецификации: .add() и .total()

Строки спецификаций (табличные части @line_items) теперь обладают методами для быстрой работы без ручных циклов:

order = SalesOrder()

# Добавление строк с авто-конвертацией типов
order.Items.add(product=prod_id, quantity=5, price=Decimal("150.00"), amount=Decimal("750.00"))

# Мгновенный расчет итогов
total_amount = order.Items.total("amount")    # Decimal("750.00")
total_quantity = order.Items.total("quantity") # 5

# Очистка строк при необходимости
order.Items.clear()

4. Active Record и быстрая работа с базой данных

Вы можете вызывать методы работы с БД прямо на объектах:

# Сохранение и удаление объекта
product = Product(name="Клавиатура", unit_price=Decimal("3500"))
product.save(db)
product.delete(db)

# Поиск и фильтрация
item = Product.get(db, 1)                     # По первичному ключу ID
all_items = Product.all(db)                   # Все записи
cheap_items = Product.filter(db, is_active=True) # По значению полей

# Сериализация в словарь и обратно
data = order.to_dict()
restored_order = SalesOrder.from_dict(data)

5. Многострочный текст (multiline=True)

Для заметок, комментариев и длинных описаний достаточно указать multiline=True:

class Task(MasterData):
    name = String(required=True)
    # Создаст QPlainTextEdit в форме и Text-колонку в SQLite:
    description = String(multiline=True)
    deadline = DateTime(required=True)

6. Сервис напоминаний о дедлайнах (ReminderService)

DECUI включает готовый фоновый сервис уведомлений с диалогом переноса сроков:

# Включение напоминаний в приложении (проверка приближающихся дедлайнов)
app.enable_reminders(
    [Task],
    date_field="deadline",
    done_field="is_completed",
    notify_before_minutes=60, # за 60 минут до срока
)

# Показ поздравительного окна при успешном достижении цели:
from decui import celebrate_goal_completed
celebrate_goal_completed(message="Цель достигнута. Отличная работа!")

7. Хелперы для быстрого тестирования

# Быстрая БД в оперативной памяти
db = Database.memory()

# Пакетное заполнение тестовыми данными (seed)
products = db.seed([
    Product(name="Товар А", unit_price=Decimal("100")),
    Product(name="Товар Б", unit_price=Decimal("200")),
])
Справочник API & Референс

Полный справочник API фреймворка DECUI

Исчерпывающее руководство по всем классам, методам, декораторам, дескрипторам полей и сервисным функциям. Вся необходимая информация собрана на этой странице — нет необходимости обращаться к исходным .md файлам.

Методы класса `Database`

Метод Сигнатура Описание
Database(path) Database(db_path: str = "erp.db") Инициализация базы данных SQLite. Автоматически выполняет хэш-миграцию схемы.
Database.memory() classmethod Database.memory() Создает чистую БД в оперативной памяти (для быстрых тестов без создания файлов).
db.save(entity) db.save(entity: Entity) -> Entity Сохраняет сущность (INSERT если id is None, иначе UPDATE) вместе со всеми строками спецификаций.
db.get(Class, id) db.get(entity_cls, id: int) -> Optional[Entity] Загружает сущность по первичному ключу вместе со всеми строками табличных частей.
db.list(Class) db.list(entity_cls) -> list[Entity] Возвращает список всех записей (быстрая выборка без загрузки строк спецификаций).
db.filter(Class, **kwargs) db.filter(entity_cls, **kwargs) -> list[Entity] Выборка записей по точным значениям полей (например: status="В работе").
db.delete(entity) db.delete(entity: Entity) Каскадно удаляет запись и все связанные с ней строки спецификаций.
db.seed(entities) db.seed(entities: list[Entity]) -> list[Entity] Пакетное сохранение списка объектов (удобно для заполнения начальных данных).

3. Метаданные классов сущностей (`__*__`)

Поведение сущностей настраивается декларативными атрибутами класса:

Атрибут Тип Назначение и пример
__section__ (или __subsystem__) str Раздел дерева навигации в левой панели: __section__ = "Склад/Остатки" (поддерживает слеши для подразделов).
__verbose_name__ str Человекочитаемое имя во множественном числе для списков и меню: __verbose_name__ = "Заказы клиентов".
__numbering__ dict Шаблон сквозной нумерации:
{"prefix": "INV", "field": "number", "pattern": "{prefix}-{year}-{seq:06d}"}
Переменные: {prefix}, {year} (4 цифры), {month} (2 цифры), {seq:0Nd} (порядковый номер с N нулями). Счётчик автоматически сбрасывается для нового года/месяца!
__defaults__ dict Значения по умолчанию для формы создания новой записи:
{"status": "Черновик", "created_date": lambda db: datetime.date.today()}
__primary_key__ str Имя первичного ключа (по умолчанию "id", INTEGER PRIMARY KEY AUTOINCREMENT).

5. Табличные части и спецификации (`@line_items` / `@tab_part`)

Табличные части объявляются как внутренние классы с декоратором @line_items:

@transaction
class Invoice(Transaction):
    customer = Ref(Customer, "Клиент", required=True)
    total    = D("Итого", read_only=True)

    @line_items
    class Items:
        product  = Ref(Product, "Товар", required=True)
        quantity = Integer("Количество", default=1, min_value=1)
        price    = D("Цена", precision=10, scale=2)
        amount   = D("Сумма", precision=10, scale=2, read_only=True)

    # Работа со строками через коллекцию self.Items (LineItemsCollection):
    @action("Пересчитать")
    def recalc(self):
        # 1. Обход строк
        for row in self.Items:
            row["amount"] = Decimal(str(row.get("quantity") or 0)) * Decimal(str(row.get("price") or 0))
            
        # 2. Быстрый подсчет итога по любой колонке
        self.total = self.Items.total("amount")

    def add_standard_item(self, product_obj, qty=1):
        # 3. Программное добавление новой строки в спецификацию:
        self.Items.add(product=product_obj._id, quantity=qty, price=product_obj.price, amount=qty * product_obj.price)
Авторасчет и управление строками в UI
  • Если колонки названы price, quantity и amount, встроенный интерфейс автоматически рассчитывает произведение прямо в ячейке при вводе!
  • Интерфейс таблицы снабжен кнопками «Добавить строку», «Удалить строку», «Вверх» и «Вниз».

6. Действия на форме, бизнес-логика и валидация (`@action`)

import datetime
from decui import action

@transaction
class ProjectTask(Transaction):
    title        = String(required=True)
    deadline     = DateTime(default=datetime.datetime.now)
    is_completed = Boolean(default=False)

    @action("Завершить задачу")
    def complete(self):
        # Валидация правил: выброс ValueError отменяет сохранение и показывает диалог пользователю
        if self.is_completed:
            raise ValueError("Задача уже завершена!")
            
        self.is_completed = True
        self.post() # Проведение документа

    @action("Продлить на неделю")
    def extend(self):
        # Стандартная арифметика дат Python (datetime + timedelta)
        current = self.deadline or datetime.datetime.now()
        self.deadline = current + datetime.timedelta(days=7)

7. Регистры остатков (`@ledger`) и сведений (`@history_register`)

# 1. Балансовый регистр (Event Sourcing)
@ledger
class WarehouseStock(Ledger):
    warehouse = Dimension("Склад")    # Разрез аналитики
    product   = Dimension("Товар")    # Разрез аналитики
    quantity  = Metric("Остаток")     # Суммируемый ресурс

# В транзакции:
def get_ledger_entries(self):
    return [
        LedgerEntry(
            register=WarehouseStock,
            dimensions={"warehouse": self.warehouse, "product": row["product"]},
            resources={"quantity": row["quantity"]},
            is_income=True, # True = приход (+), False = расход (-)
        )
        for row in self.Items
    ]

# Запрос мгновенного баланса:
balances = get_ledger_balance(db, WarehouseStock, warehouse=1, group_by=["product"])

# 2. Регистр сведений (периодические параметры)
@history_register
class PriceHistory(HistoryRegister):
    product = Dimension("Товар")
    price   = Resource("Цена")

# Запись и чтение среза последних:
set_record(db, PriceHistory, dimensions={"product": 1}, resources={"price": 1500.00})
latest = get_latest(db, PriceHistory, product=1) # -> {"price": 1500.00}

12. Частые вопросы и архитектурные тонкости (FAQ)

1. Загрузка спецификаций: почему db.list() не возвращает строки?
В целях высокой производительности метод db.list(Class) загружает только заголовки (шапки) документов для отображения в таблице. Чтобы загрузить документ со всеми строками спецификаций, используйте db.get(Class, id) или Class.get(db, id).
2. Как работает клонирование («Копировать») в списках?
Кнопка «Копировать» в ListView автоматически клонирует выбранную запись вместе со всеми строками спецификаций, но сбрасывает id и уникальный номер (number / code), чтобы новая запись получила новый уникальный номер из счётчика автонумерации.
3. Как обновляется схема базы данных при добавлении новых полей?
DECUI вычисляет криптографический хэш структуры всех моделей. При изменении полей или таблиц фреймворк выполняет автоматическую чистую миграцию, поэтому вам никогда не придётся писать ручные SQL-скрипты миграций.
