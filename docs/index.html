Концепции и архитектура DECUI

Добро пожаловать в пошаговый интерактивный учебник по DECUI — декларативному Python-фреймворку для разработки настольных бизнес-приложений и ERP-систем.

Первый запуск в DECUI Studio

  1. В клоне проекта выполните uv run decui studio. Если DECUI уже установлен в активном окружении, выполните decui studio.
  2. Нажмите «Открыть пример „Заказы и накладные“», затем «Запустить». В разделе «Склад → Заказы» откройте готовый заказ, создайте накладную на его основании и проведите её.
  3. Вернитесь в Studio. На вкладке «Объект» откройте «Накладные», добавьте строковое поле «Номер доставки» с именем delivery_code и снова запустите приложение, чтобы увидеть новое поле.
  4. Сохраните проект. Через «Действия → Экспорт Python» можно получить исходник app.py.

Зачем нужен специализированный фреймворк?

В учетных системах обычного простого CRUD недостаточно. Здесь требуется:

  • Разделение на справочники и транзакции: товары и контрагенты хранятся как справочники (Master Data), а чеки, счета и накладные — как документы, привязанные к календарному моменту.
  • Проведение документов: пока документ черновик — остатки не меняются. При проведении он формирует записи в регистрах (движения). При отмене проведения — движения удаляются.
  • Спецификации строк (Master-Detail): заказ всегда состоит из шапки (клиент, дата) и строк (товар, количество, цена).
  • Автоматический расчет остатков: вместо медленного пересчета миллионов строк история собирается в регистры накопления.

Первое приложение

Создайте справочник товаров, сохраните запись и добавьте поле в Python. DECUI создаст карточку, список и таблицу SQLite из одного класса.

1. Создайте проект и запустите его

Из корня репозитория DECUI выполните команды ниже. Нужны Python 3.12+ и uv. Команды одинаковы в Bash и PowerShell.

uv sync --locked --inexact
uv run --locked decui new warehouse --template basic
cd warehouse
uv run --locked decui run

В списке «Товары» нажмите «Новый», введите «Чай» и цену 125,50, затем сохраните карточку. Закройте окно и повторите последнюю команду. Товар останется в списке. База хранится в warehouse/data.sqlite3.

Нажмите Ctrl+F, введите «Чай» и нажмите Enter, чтобы перейти к результатам. Ещё одно нажатие Enter откроет выбранную карточку. Если условия слишком узкие, кнопка «Сбросить» очистит поиск и отбор.

В карточке Ctrl+S (⌘S на macOS) сохраняет правки и оставляет карточку открытой. При попытке закрыть карточку с несохранёнными правками DECUI предложит сохранить их, выйти без сохранения или продолжить редактирование.

2. Добавьте поле в app.py

Декоратор @master_data регистрирует справочник. String задаёт текстовое поле, а Decimal задаёт поле для цены. Аргумент start=Product открывает список товаров при запуске.

Содержимое сгенерированного app.py 
from decui import Decimal, ERPApplication, MasterData, String, master_data


@master_data
class Product(MasterData):
    __verbose_name__ = "Товары"
    __section__ = "Склад"

    name = String("Наименование", required=True)
    price = Decimal("Цена", scale=2, min_value=0)


if __name__ == "__main__":
    app = ERPApplication(title="Учёт товаров", db_path="data.sqlite3", start=Product)
    raise SystemExit(app.run())

В warehouse/app.py импортируйте Integer из decui и добавьте в класс Product строку priority = Integer("Приоритет", default=3). Перезапустите приложение и откройте «Чай». Прежние название и цена сохранятся. Задайте приоритет 5 и сохраните. У нового товара начальный приоритет равен 3.

3. Проверьте проект в терминале

Закройте окно и выполните команды из папки warehouse. Первая проверит схему. Вторая запустит тест из test_app.py. Тест сохраняет и читает товар в отдельной базе в памяти.

Дополнительный проект «Мои цели» со связями и отчётом

Вернитесь в корень репозитория. Создайте папку my_goals командой mkdir my_goals и перейдите в неё.

Запустите «Мои цели»

Скопируйте весь блок в app.py и выполните uv run --locked decui run.

from datetime import datetime, timedelta
from typing import ClassVar

from decui import (
    Boolean, Catalog, Column, Database, DateTime, ERPApplication,
    Ref, Report, String, catalog, report,
)


def next_week() -> datetime:
    return datetime.now().replace(second=0, microsecond=0) + timedelta(days=7)


@catalog
class Goal(Catalog):
    __verbose_name__ = "Цели"
    name: String = String("Название", required=True)
    deadline: DateTime = DateTime("Срок", required=True, default=next_week)


@catalog
class Task(Catalog):
    __verbose_name__ = "Задачи"
    name: String = String("Название", required=True)
    goal: Ref = Ref(Goal, "Цель", required=True, related_list="Задачи цели")
    description: String = String("Описание", multiline=True)
    deadline: DateTime = DateTime("Срок", required=True, default=lambda: next_week() - timedelta(days=6))
    is_completed: Boolean = Boolean("Выполнено", default=False)

    def before_save(self, db: Database) -> None:
        parent = db.get(Goal, self.goal)
        if parent is not None and self.deadline > parent.deadline:
            raise ValueError("Срок задачи не может быть позже срока цели.")


@report
class PendingTasks(Report):
    title = "Открытые задачи"
    auto_run = True
    columns: ClassVar[list[Column]] = [
        Column("Задача", "name", width=0),
        Column("Срок", "deadline", width=170),
    ]

    def execute(self, db: Database, **params: object) -> list[dict[str, object]]:
        return [
            {"name": task.name, "deadline": task.deadline.strftime("%d.%m.%Y %H:%M")}
            for task in db.filter(Task, is_completed=False, order_by="deadline")
        ]


if __name__ == "__main__":
    app = ERPApplication(title="Мои цели", app_id="my-goals", start=Goal)
    app.enable_reminders([Task])
    raise SystemExit(app.run())

app_id задаёт постоянный каталог приложения в данных пользователя. Оставляйте его прежним, чтобы после перезапуска открывались те же записи. start=Goal открывает список целей сразу.

Проверьте сценарий

  1. В списке «Цели» нажмите «Новый», введите название и сохраните карточку.
  2. В разделе «Задачи цели» нажмите «Новый». Поле «Цель» заполнится автоматически. Укажите название и срок.
  3. Попробуйте поставить задаче срок позже срока цели. При сохранении появится сообщение из before_save.
  4. Откройте «Открытые задачи». Отметьте задачу выполненной и сформируйте отчёт снова. Задача исчезнет из отчёта.
  5. Создайте задачу со сроком через 30 минут и подождите до следующей проверки напоминаний. Закройте и запустите приложение снова, чтобы проверить сохранение записей.

Добавьте своё правило

Сохраните цель и связанную задачу, затем сделайте резервную копию. Импортируйте Integer и добавьте в Task поле priority = Integer("Приоритет", default=1, min_value=1, max_value=3). Оставьте app_id="my-goals" и перезапустите приложение. AutoForm вызывает create_editor() для числового редактора, а ListView берёт заголовок колонки из тех же метаданных. Проверьте из Python: сразу после обновления db.get(Task, task_id).priority возвращает None, а Task().priority возвращает 1. ID и ссылка на цель сохраняются. Откройте старую карточку, явно установите приоритет и сохраните. При новом чтении вернётся записанное число.

  • Catalog даёт список и карточку. Дескрипторы String, DateTime и Boolean задают типы данных и редакторы.
  • Ref(..., related_list="Задачи цели") добавляет в карточку связанный список. С on_delete="CASCADE" удаление цели удалит и её задачи.
  • before_save(db) проверяет правила при любом сохранении, в том числе из напоминания. db.get(...) и db.filter(...) читают данные через Python.
  • ERPApplication(..., first_run=seed) один раз вызывает функцию seed(db) для начальных данных. Если функция завершится ошибкой, её изменения откатятся.

Как развить пример до «Цель. Код будущего»

  • Последовательность этапов. В before_save прочитайте задачи цели через db.filter, сравните срок с соседними этапами и проверьте, что предыдущие выполнены.
  • Прогресс и статус. Считайте долю выполненных этапов после записи и удаления задачи в after_save и after_delete. Сохраните результат в поле цели с read_only=True. Изменения задачи и цели войдут в одну транзакцию.
  • Отчёт по целям. Используйте RefParam для отбора. В execute верните строку с _style="group" для каждой цели, затем строки её этапов со стилями completed, current и future. Чтобы порядок групп сохранялся, задайте sortable=False.

Полный код этих правил и начальные данные есть в примере «Цель. Код будущего». Из локального репозитория он запускается командой uv run --locked python -m examples.future_goals.

DECUI полностью поддерживает автодополнение и проверку типов в современных IDE (VS Code, PyCharm, Cursor):

  • Аннотации типов: вы можете писать name: str = String("Имя") или минималистично name: str, age: int = 18. Фреймворк автоматически распознает тип и создаст нужный дескриптор.
  • Автодополнение в конструкторе: благодаря стандарту @dataclass_transform при создании Product(...) IDE подсказывает все доступные параметры.
  • Встроенные поля документов: любой Document уже имеет типизированные поля date, number, posted и id.
  • Служебные атрибуты: при вводе __ внутри класса IDE подсказывает __verbose_name__, __section__, __numbering__, __defaults__.
  • Интроспекция в коде: в любой момент можно узнать поля класса через Product.field_names() или Product.fields().

Практический пример: Категории и Товары с автонумерацией

from decui import master_data, MasterData, String, Decimal as D, Ref

@master_data
class Category(MasterData):
    __verbose_name__ = "Категории"
    __section__      = "Склад/Справочники"

    title = String("Название категории", required=True)

@master_data
class Product(MasterData):
    __verbose_name__ = "Товары"
    __section__      = "Склад/Справочники"
    # Автонумерация: PRD-000001, PRD-000002...
    __numbering__    = {"prefix": "PRD", "pattern": "{prefix}-{seq:06d}"}

    code     = String("Артикул", read_only=True)
    name     = String("Наименование", required=True)
    category = Ref(Category, "Категория", representation_field="title")
    price    = D("Цена закупки", precision=10, scale=2, min_value=0)
💡 Как работает Ref(..., representation_field="title")?
Фреймворк превратит это поле в выпадающий список (комбобокс), подгрузит доступные категории из базы данных и будет показывать значение поля title вместо непонятного числового ID.

Документы и спецификации строк (@line_items)

Документ отражает факт хозяйственной операции (счет, приходная накладная, чек продажи). В отличие от справочника, он имеет дату, статус проведения и табличную часть со строками.

Создание документа «Заказ покупателя»

from decimal import Decimal
from decui import transaction, Transaction, String, Integer, Decimal as D, Ref, line_items, action

@transaction
class SaleOrder(Transaction):
    __verbose_name__ = "Заказы клиентов"
    __section__      = "Продажи"
    # Шаблон: ORD-2026-000001
    __numbering__    = {"prefix": "ORD", "pattern": "{prefix}-{year}-{seq:06d}"}

    customer = String("Клиент", required=True)
    total    = D("Итоговая сумма", precision=10, scale=2, read_only=True, default=Decimal("0.00"))

    # Табличная часть со строками товаров
    @line_items
    class Items:
        product  = Ref(Product, "Товар", representation_field="name")
        quantity = Integer("Кол-во", default=1, min_value=1)
        price    = D("Цена продажи", precision=10, scale=2)
        amount   = D("Сумма", precision=10, scale=2, read_only=True)

    # Кнопка действия на форме заказа
    @action("Рассчитать сумму")
    def calculate_total(self):
        for row in self.Items:
            qty = Decimal(str(row.get("quantity") or 0))
            prc = Decimal(str(row.get("price") or 0))
            row["amount"] = qty * prc
        self.total = self.Items.total("amount")

# product — сохранённый товар; order — новый документ.
order = SaleOrder(customer="Клиент")
order.Items.add(product=product.id, quantity=2, price=Decimal("12.50"))
Автоматический расчет строк в UI
Если в табличной части используются стандартные имена price, quantity и amount, встроенный виджет таблицы DECUI автоматически умножает количество на цену при вводе прямо в интерфейсе!

Как описывать бизнес-логику и проверки (Валидация, @action, Исключения)

Бизнес-логика в DECUI пишется на чистом Python прямо в методах сущности. Достаточно добавить декоратор @action("Текст кнопки"):

import datetime
from decui import transaction, Transaction, String, DateTime, action

@transaction
class TaskOrder(Transaction):
    title = String("Задача", required=True)
    deadline = DateTime("Дедлайн", default=datetime.datetime.now)
    status = String("Статус", default="В работе")

    # 1. Валидация и проверка бизнес-правил
    @action("Завершить задачу")
    def complete(self):
        # Если правило нарушено, вызываем ValueError:
        # DECUI автоматически перехватит ошибку, отменит сохранение
        # и покажет красивое диалоговое окно пользователю!
        if self.status == "Завершена":
            raise ValueError("Задача уже завершена ранее!")
            
        self.status = "Завершена"

    # 2. Арифметика дат и времени в логике
    @action("Продлить на 3 дня")
    def extend_deadline(self):
        current = self.deadline or datetime.datetime.now()
        # Стандартная работа с datetime и timedelta в Python
        self.deadline = current + datetime.timedelta(days=3)
Жизненный цикл выполнения действия (@action):
  1. Пользователь нажимает кнопку на форме.
  2. DECUI считывает введённые значения из всех полей и табличных частей в объект self.
  3. Выполняется ваш Python-метод. Если возникнет ValueError, сохранение отменяется, а пользователю показывается текст ошибки.
  4. При успешном завершении объект автоматически сохраняется в базу данных (db.save(self)).
  5. Форма немедленно обновляет экранные виджеты новыми значениями.
Шаг 4 из 8

Складской учёт и регистры остатков (@ledger)

Сердце любой системы учета — Регистры остатков (Ledgers). Они работают по принципу Event Sourcing: документы формируют записи изменений (приход +, расход -), а регистр мгновенно отдает актуальный баланс.

1. Определение складского регистра

from decui import ledger, Ledger, Dimension, Metric

@ledger
class StockLedger(Ledger):
    warehouse = Dimension("Склад")    # Разрез аналитики
    product   = Dimension("Товар")    # Разрез аналитики
    quantity  = Metric("Количество")  # Ресурс (число)

2. Генерация движений при проведении заказа

Добавим в документ метод get_ledger_entries(). Когда пользователь нажмет «Провести и закрыть», DECUI автоматически запишет расход со склада:

from decui import LedgerEntry

@transaction
class SaleOrder(Transaction):
    ...
    # Метод формирования движений при проведении
    def get_ledger_entries(self):
        entries = []
        for row in self.Items:
            entries.append(LedgerEntry(
                register=StockLedger,
                dimensions={"warehouse": "Основной", "product": row["product"]},
                resources={"quantity": row["quantity"]},
                is_income=False,  # False = расход со склада (-qty)
            ))
        return entries

class PurchaseReport(Report):

    auto_run = True
    supplier = RefParam("Поставщик", Supplier, from_record=True)
    date_from = DateParam("С", default=date(2026, 11, 1))

    def execute(
        self, db: Database, *, date_from: date, date_to: date, supplier: int | None = None,
    ) -> list[dict]:
        rows = []
        filters = {"supplier": supplier} if supplier is not None else {}
        orders = db.filter(
            PurchaseOrder,
            date__date_range=(date_from, date_to),
            include_table_parts=True,

        for order in orders:

                    number=order.number,
                    product=products.get(item["product"], ""),
                    amount=item["amount"],
                    _entity_class=PurchaseOrder,
                    _entity_id=order.id,
                ))
        return rows

@master_data
class Product(MasterData):
    __verbose_name__ = "Товары"
    __section__ = "Склад"

    name = String("Наименование", required=True)
    price = D("Цена", precision=10, scale=2, min_value=0)

@master_data

    name = String("Наименование", required=True)

@transaction
class PurchaseOrder(Transaction):

    supplier = Ref(Supplier, "Поставщик", required=True, related_list="Заказы поставщику")

        amount = D("Сумма", scale=2, read_only=True)

    def on_validate(self):
        return [] if self.Items else ["Добавьте хотя бы одну строку заказа."]

    def before_save(self, db):
        prices = []
        for line, row in enumerate(self.Items, start=1):
            record = get_latest(
                db, Prices, on_date=self.date,
                product=row["product"], supplier=self.supplier,

                    "нет допустимой цены поставщика."
                )
            prices.append(record["price"])

        for row, price in zip(self.Items, prices, strict=True):
            row["unit_price"] = price
            row["amount"] = (row["quantity"] * price).quantize(
                Decimal("0.01"), rounding=ROUND_HALF_UP
            )
        self.total = self.Items.total("amount")

def seed_demo(db: Database):
    with db.transaction():
        if db.filter(PurchaseOrder, number="DEMO-NOV"):
            return
        products = db.list(Product)
        product = products[0] if products else db.save(Product(name="Кофе", price=Decimal("99")))
        north = db.save(Supplier(name="Север"))
        south = db.save(Supplier(name="Юг"))
        for supplier, day, price in (
            (north, date(2026, 11, 1), "12.50"),
            (north, date(2026, 12, 1), "15.00"),
            (south, date(2026, 11, 1), "0.00"),
        ):
            set_record(db, Prices, dimensions={"product": product.id, "supplier": supplier.id},
                       resources={"price": Decimal(price)}, period=day)
        for number, supplier, moment in (
            ("DEMO-NOV", north, datetime(2026, 11, 30, 23, 59, 59)),
            ("DEMO-JAN", south, datetime(2027, 1, 1)),
        ):
            order = PurchaseOrder(number=number, supplier=supplier.id, date=moment)
            order.Items.add(product=product.id, quantity=2)
            db.save(order, validate=True)

Колонки списка

В редакторе объекта Studio нажмите «Настроить колонки списка». Отметьте нужные поля, перетащите их в нужном порядке и при желании выберите начальную сортировку. В Python те же настройки доступны через __list_columns__ = ("price", "name") и __list_order__ = "-price".

Отбор по полям

В основном списке нажмите «Отбор…», отметьте поля и задайте условия. Можно сравнить числа и даты, найти часть текста или проверить, заполнено ли поле. Условие «Диапазон» включает обе границы. Для поля с датой и временем укажите время обеих границ. Все условия действуют одновременно вместе с текстовым поиском. При переходе из списка в карточку и обратно сохраняются поиск, отбор, сортировка и выделенная запись, если она по-прежнему подходит под условия. Поиск, отбор и сортировка сохраняются в базе между запусками, отдельно для каждой учётной записи. Чтобы убрать условия, нажмите «Сбросить» и примените изменения.

Для часто используемого отбора выберите «Варианты → Сохранить вариант…» и введите название. Команда «Открыть вариант…» восстановит его поиск, отбор и сортировку. Варианты хранятся отдельно для каждого списка и каждой учётной записи.

Выгрузка списка в CSV

В основном списке справочника или документа выберите «CSV → Выгрузить список…». Выгрузка берёт видимые колонки и результаты текущего поиска в порядке сортировки, с подписями, отображаемыми в таблице. Для обратной загрузки используйте шаблон импорта.

Импорт справочника из CSV

В списке справочника откройте «CSV → Сохранить шаблон CSV…», чтобы получить файл с заголовками доступных полей. Заполните строки и выберите «CSV → Импорт CSV…». Если файл уже есть, сохраните его в UTF-8, оставив первой строкой заголовки колонок. Если заголовки совпадают с именами полей Python или их подписями, DECUI сопоставит их автоматически. При несовпадении откроется диалог, где можно назначить поле или пропустить лишнюю колонку. Для ссылки укажите ID или точное название записи. Если название состоит из цифр, напишите название:123. Если названия совпадают, укажите ID нужной записи. Для дат используйте формат ISO. Пустые ячейки оставляют значения по умолчанию. Studio и готовое приложение используют те же метаданные, поэтому дополнительные настройки импорта не нужны. Проверьте предпросмотр и подтвердите импорт.

Чтобы обновить записи, включите свойство «Уникальное» у строкового или целочисленного поля, например артикула. При импорте выберите это поле как ключ. Строки с найденным ключом обновляются, остальные создаются при наличии права. Пустые ячейки при обновлении оставляют прежние значения. Если сохранение одной из строк не удалось, изменения по всему файлу откатываются.

Кнопки действий в Studio

Напишите в редакторе объекта метод, который можно вызвать без аргументов, кроме self. Нажмите «Кнопки действий…», выберите метод и задайте подпись кнопки. При предпросмотре ошибки сохранения, действий и отчётов попадают в журнал сразу, даже когда приложение продолжает работать. Studio добавит команду к форме. Проведение из Python

В бизнес-логике используйте db.post(document). DECUI проверит права, заполнение и последовательность, выполнит команду проведения и заменит движения. При ошибке запись и движения откатываются. Диалог формы использует тот же метод. Чтобы вернуть сохранённый документ в черновик и удалить его движения, нажмите «Отменить проведение» или вызовите document = db.unpost(document). Кнопка «Движения» открывает строки регистров этого документа по вкладкам. Для обычной команды формы используйте db.execute_command(document, "method_name"). Сохранение и обновление движений команды проходят в одной транзакции.

5. Табличные части и спецификации (`@line_items` / `@tab_part`)

Табличные части объявляются как внутренние классы с декоратором @line_items:

@transaction
class Invoice(Transaction):
    customer = Ref(Customer, "Клиент", required=True)
    total    = D("Итого", read_only=True)

    @line_items
    class Items:
        product  = Ref(Product, "Товар", required=True)
        quantity = Integer("Количество", default=1, min_value=1)
        price    = D("Цена", precision=10, scale=2)
        amount   = D("Сумма", precision=10, scale=2, read_only=True)

    # Работа со строками через коллекцию self.Items (LineItemsCollection):
    @action("Пересчитать")
    def recalc(self):
        # 1. Обход строк
        for row in self.Items:
            row["amount"] = Decimal(str(row.get("quantity") or 0)) * Decimal(str(row.get("price") or 0))
            
        # 2. Быстрый подсчет итога по любой колонке
        self.total = self.Items.total("amount")

    def add_standard_item(self, product_obj, qty=1):
        # 3. Программное добавление новой строки в спецификацию:
        self.Items.add(product=product_obj.id, quantity=qty, price=product_obj.price, amount=qty * product_obj.price)

12. Частые вопросы и архитектурные тонкости (FAQ)

1. Загрузка спецификаций: почему db.list() не возвращает строки?
Методы db.list(Class) и db.filter(Class, ...) по умолчанию загружают шапки записей. Чтобы редактировать или проводить документы с табличными частями, загрузите их через db.get(Class, id) или передайте include_table_parts=True в выборку. Попытка сохранить шапку такой записи вызовет ValueError.
2. Живой поиск, быстрое создание Ref (+) и сортировка в списках
В списках ListView можно искать с помощью Ctrl+F, сортировать числа, даты и суммы, видеть названия связанных записей и подтверждать удаление. Клавиша Esc в поле поиска очищает запрос. Кнопка «Сбросить» также снимает отбор по полям. F5 обновляет список и сохраняет выбор, если запись по-прежнему видна. В формах AutoForm у ссылочных полей есть поиск и кнопка + для создания элемента справочника без закрытия текущей формы. Вложенная карточка запрашивает решение о несохранённых правках при закрытии или нажатии Esc.
3. Как обновляется схема базы данных при добавлении новых полей?
DECUI отслеживает хэш схемы и выполняет неразрушающий апгрейд (ALTER TABLE ADD COLUMN) при добавлении новых полей — существующие данные пользователей сохраняются!
4. Как обрабатываются ошибки базы данных и удаление проведённых документов?
На уровне UI ошибки ограничений SQLite/SQLAlchemy (UNIQUE, FOREIGN KEY, NOT NULL, блокировка БД) автоматически переводятся в понятные русскоязычные сообщения, а технические подробности скрываются в деталях диалога. При удалении документа через db.delete(doc) или кнопку «Удалить» в списке все его движения в регистрах очищаются автоматически в той же транзакции.
Руководство разработчика

Полный гайд по DECUI: архитектура, права и практики

Сквозное руководство по построению настольных учётных систем на DECUI — от жизненного цикла сохранения и маршрутов согласования до прав доступа, печатных форм и чек-листа лучших практик.

1. Жизненный цикл сохранения и проведения

Единые правила в хуках класса работают одинаково и в форме AutoForm, и при прямых вызовах db.save() / db.post() в Python и тестах:

Этап / метод Когда выполняется Назначение
on_validate(self) В форме всегда; в Python при db.save(doc, validate=True) и db.post(doc) Возвращает список ошибок list[str] без побочных эффектов.
before_save(self, db) При каждом сохранении (в форме и в Python) Пересчёт итогов, подстановка цен, бизнес-проверки (ValueError откатывает запись).
after_save(self, db) После сохранения шапки и строк в транзакции Пост-обработка после фиксации данных.
before_delete / after_delete При удалении через db.delete(obj) Проверки и очистка; движения регистров документа удаляются автоматически в той же транзакции.
db.post(doc) / db.unpost(doc) Проведение или отмена проведения документа Проверяет права, последовательность __sequence__, запускает команду и переписывает движения регистров.

2. Маршруты согласования (Workflow)

Для управления статусами, ролями и назначенными согласующими задайте атрибут __workflow__ в классе сущности:

from decui import Document, String, Transition, Workflow, document

@document
class Invoice(Document):
    status = String("Статус", default="Черновик", read_only=True)
    approval_assignee = String("Согласующий")

    __workflow__ = Workflow(
        field="status",
        initial="Черновик",
        states=("Черновик", "На согласовании", "Утверждён"),
        transitions=(
            Transition("На согласование", "Черновик", "На согласовании", roles=("manager", "admin")),
            Transition("Утвердить", "На согласовании", "Утверждён", roles=("admin",), assigned_only=True),
        ),
        post_states=("Утверждён",),  # проводить можно только утверждённый документ
    )

# Программный переход и история:
invoice = db.transition(invoice, "На согласование")
events = db.workflow_history(invoice)

В карточке сохранённого документа автоматически появляются кнопки доступных текущей роли переходов и кнопка «История».

3. Учётные записи и разграничение прав

Передайте local_accounts=True в ERPApplication(...), чтобы при первом запуске создать администратора и требовать вход по логину/паролю. На уровне сущности доступны настройки:

  • __owner_field__ = "author" — доступ к записи остаётся у её создателя и роли admin (плюс назначенный согласующий для перехода).
  • __permissions__ — матрица операций {"read": (...), "create": (...), "update": (...), "delete": (...), "post": (...)}.
  • __field_read_roles__ / __field_write_roles__ — скрытие и защита отдельных полей и колонок (например, "Items.cost").
  • __command_roles__ — ограничение кнопок @action / @command по ролям.

5. Сквозной мини-проект: от складов до отчёта по регистрам

from decui import (
    Column, Database, Integer, Ledger, LedgerEntry, MasterData, Metric,
    QueryReport, Ref, RefDimension, String, Transaction,
    ledger, line_items, master_data, register_report_rows, report, transaction,
)

@master_data
class Warehouse(MasterData):
    name = String("Склад", required=True, unique=True)

@master_data
class Product(MasterData):
    name = String("Товар", required=True)

@ledger
class StockLedger(Ledger):
    warehouse = RefDimension(Warehouse, "Склад")
    product = RefDimension(Product, "Товар")
    qty = Metric("Количество")

@transaction
class Receipt(Transaction):
    warehouse = Ref(Warehouse, "Склад", required=True)

    @line_items
    class Items:
        product = Ref(Product, "Товар", required=True)
        qty = Integer("Количество", min_value=1, default=1)

    def get_ledger_entries(self):
        return [
            LedgerEntry(
                register=StockLedger,
                dimensions={"warehouse": self.warehouse, "product": row["product"]},
                resources={"qty": row["qty"]},
                is_income=True,
            )
            for row in self.Items
        ]

@report
class StockBalanceReport(QueryReport):
    title = "Остатки по складам"
    auto_run = True
    columns = [
        Column("Склад", "warehouse"),
        Column("Товар", "product"),
        Column("Остаток", "qty", align="right", aggregate="sum"),
    ]

    def execute(self, db: Database, **_kw):
        return register_report_rows(db, StockLedger, ["warehouse", "product", "qty"])

6. Чек-лист лучших практик

7 правил надёжного приложения DECUI
  1. Запуск окна и first_run держите под if __name__ == "__main__":, чтобы корректно работали decui check и тесты.
  2. Перед редактированием или проведением загружайте строки через db.get(Class, id) или include_table_parts=True.
  3. Для денег и количеств используйте Decimal, а не float.
  4. В Report.execute() загружайте справочники одним словарём и возвращайте числа — форматируйте через Column.
  5. Бизнес-проверки держите в on_validate() и before_save(db), чтобы они действовали и в UI, и в Python API.
  6. Для хранения базы у пользователей задавайте app_id, а перед обновлением схемы проверяйте копию через decui check --backup.
  7. При тестировании нескольких БД изолированные модели создаются автоматически на каждый Database.memory() без конфликтов.
