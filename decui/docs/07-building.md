# Сборка приложения и обновление базы

## Сборка своего приложения

В активном окружении с DECUI перейдите в каталог приложения и укажите точку входа.
Команда одинакова в Bash и PowerShell.

```bash
decui build app.py
```

CLI передаёт PyInstaller путь к DECUI из активного окружения, в том числе
при установке из исходников через `uv sync` или `pip install -e .`.
Результат находится в `dist/app.exe` на
Windows или `dist/app` на Linux. Имя берётся из имени файла точки входа.
Если опустить аргумент, DECUI ищет `app.py`, затем `main.py`. Для сборки
Windows-версии запустите команду на Windows. На компьютере пользователя
устанавливать Python не требуется.

## Сборка примера из репозитория

Из корня репозитория выполните следующие команды.

```bash
uv sync --locked --inexact
uv run --locked python build_exe.py
```

Скрипт по умолчанию собирает `examples/simple.py` в `dist/ERP.exe` на Windows
или `dist/ERP` на Linux. Путь к другому скрипту можно передать первым
аргументом, а имя изменить через `--name`. Скрипт пересоздаёт каталоги
`build/` и `dist/` в корне репозитория. Параметр `--clean-db` удаляет
оттуда файлы `*.db`.

## При первом запуске

Исполняемый файл использует настройку базы из исходного приложения.
При заданном `app_id` и стандартном `db_filename` база находится
в `DECUI/<app_id>/data.sqlite3` внутри каталога данных пользователя.
Явный `db_path` задаёт путь к базе. Например, `examples/simple.py`
создаёт `erp_demo.db` в рабочем каталоге.

При открытии существующей базы DECUI добавляет новые таблицы и столбцы.
Поддерживаемые переименования задаются явно. Старые строки получают
`NULL` в новых столбцах, поэтому заполните их отдельно, если этого требуют
правила приложения. См. [миграцию схемы](09-advanced.md#автоматическая-миграция-схемы).

## Репетиция обновления

Сохраните снимок рабочего приложения через «Данные → Сохранить резервную копию»
или `db.backup(path)`. Из каталога приложения проверьте обновлённый код.

```bash
decui check app.py --backup /path/to/before-update.sqlite3
```

Проверка применит схему на временном экземпляре снимка и проверит ссылки.
Для прогона с реальными записями используйте отдельную копию. После проверки
запустите рабочее приложение с прежним `app_id` или `db_path`.
