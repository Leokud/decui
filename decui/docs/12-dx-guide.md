# Руководство по Developer Experience (DX) в DECUI

DECUI спроектирован так, чтобы разработка учетных систем на Python была быстрой, понятной и не требовала рутинного шаблонного кода (boilerplate). В этой главе описаны возможности для улучшения эргономики работы разработчика.

---

## 1. Консольная утилита `decui` (CLI)

Фреймворк поставляется со встроенной CLI-утилитой `decui`, доступной из терминала или через `python -m decui.cli`.

Команды ниже рассчитаны на активное окружение с DECUI. Если вы работаете
из клона репозитория, используйте `uv run --locked decui` в корне
или во вложенной папке проекта.
[Инструкция по установке](01-quickstart.md#установка)

### Создание нового проекта

Выберите `basic` для первого приложения. Он создаёт справочник товаров.

```bash
decui new warehouse --template basic
cd warehouse
decui run
```

Выберите `orders`, чтобы посмотреть работу клиентов, заказов со строками
и отчёта. По умолчанию `decui new my_erp` использует этот шаблон.

Оба шаблона создают приложение `app.py`, инструкции `README.md` и
`test_app.py` с примером сохранения и чтения данных через `Database.memory()`.
Файл `.gitignore` исключает базы SQLite и их журналы, кэши Python и pytest,
виртуальное окружение и каталоги сборки.

### Проверка схем и моделей: `decui check [файл]`
Импортирует точку входа, проверяет объявления сущностей и создаёт тестовую
схему SQLite в памяти. Поместите запуск окна и заполнение демо-данными
под `if __name__ == "__main__"`, чтобы эти действия выполнялись только
при запуске приложения.

```bash
decui check
```

При успешной проверке CLI выводит сводку на русском языке (`Проверка пройдена (app.py): сущностей — ..., отчётов — ...`).
Если целевая модель ссылки отсутствует, проверка перечисляет такие ссылки
в полях сущностей, строках документов, параметрах отчётов и измерениях
регистров. Например, сообщение с путём `SalesOrder.Items.product` указывает
на поле `product` в табличной части `Items`. Проверьте имя целевой модели,
её регистрацию через `@master_data` или `@transaction` и импорт модуля
с этой моделью из точки входа.

Для [проверки обновления существующей базы](07-building.md#репетиция-обновления)
передайте `--backup` с путём к резервной копии. При сбое подключения или
ограничений БД на уровне UI (`AutoForm`, `ListView`, `ReportView`, напоминания)
DECUI преобразует технические ошибки SQLAlchemy/SQLite в понятные русские
сообщения, убирая детали и стектрейс в раскрываемую область диалога.

### Запуск приложения: `decui run [файл]`
Запускает `app.py` или `main.py` из текущего каталога. Используйте каталог
приложения как рабочий, если в его коде есть относительные пути к данным.

```bash
decui run
# или указать конкретный файл
decui run custom_app.py
```

### Запуск тестов: `decui test`
Передаёт аргументы в `pytest` в исходном порядке. На Linux без дисплея
CLI задаёт `QT_QPA_PLATFORM=offscreen`, если переменная ещё не установлена.

```bash
decui test
decui test -q test_app.py
decui test -k order
```

### Сборка дистрибутива: `decui build [файл]`
Собирает оконное приложение в единый файл через PyInstaller и передаёт ему
путь к DECUI из активного окружения.

```bash
decui build app.py
```

См. [сборку и расположение результата](07-building.md).

## 2. Автоматический вывод названий полей (Auto-naming)

Раньше для каждого поля требовалось обязательно указывать русское или английское отображаемое имя:
```python
# Старый синтаксис
name = String("Наименование", required=True)
unit_price = Decimal("Цена за единицу", scale=2)
```

Теперь аргумент `display_name` опционален. Если имя опущено, DECUI автоматически формирует читабельную подпись из имени атрибута:

```python
# Современный краткий синтаксис:
name = String(required=True)                  # Подпись: "Name"
unit_price = Decimal(scale=2, currency="RUB") # Подпись: "Unit price"
customer_phone = String()                     # Подпись: "Customer phone"
is_active = Boolean(default=True)             # Подпись: "Is active"
customer = Ref(Customer, required=True)       # Подпись: "Customer"
```

> **Совет:** Явное отображаемое имя по-прежнему поддерживается первым позиционным аргументом: `name = String("Название товара", required=True)`.

## 3. Коллекция строк спецификаций (`LineItemsCollection`)

Спецификации документов (`@line_items` / `@tab_part`) теперь оборачиваются в `LineItemsCollection`. Это сохраняет 100% совместимость с обычным `list`, добавляя методы `.add()` и `.total()`:

### Добавление строк через `.add(**kwargs)`
Автоматически валидирует и приводит типы значений в соответствии с дескрипторами:

```python
order = SalesOrder()

# Быстрое добавление строк
order.Items.add(
    product=product_id,
    quantity=5,
    price=Decimal("120.00"),
    amount=Decimal("600.00"),
)
```

### Подсчет итогов через `.total(field)`
Больше не нужно писать циклы для суммирования:

```python
total_sum = order.Items.total("amount")   # Decimal("600.00")
total_qty = order.Items.total("quantity") # 5
```

### Совместимость с обычными списками
Коллекция наследует стандартный `list`, поэтому все привычные операции Python работают «из коробки»:

```python
len(order.Items)          # Количество строк
order.Items[0]            # Доступ по индексу
for row in order.Items:   # Итерация
    print(row["amount"])
order.Items.clear()       # Очистка строк
```

## 4. Паттерн Active Record и методы сущностей

Вы можете использовать привычный объектный стиль работы с базой данных вместо вызовов `db.save(entity)`:

```python
# 1. Сохранение
product = Product(name="Монитор 27\"", unit_price=Decimal("25000.00"))
product.save(db)
print(product.id)  # ID назначен автоматически

# 2. Получение по ID (включая строки спецификаций)
loaded = Product.get(db, 1)

# 3. Список всех записей
all_products = Product.all(db)

# 4. Фильтрация по значениям полей
active_items = Product.filter(db, is_active=True)

# 5. Удаление
product.delete(db)
```

## 5. Сериализация и десериализация (`to_dict` / `from_dict`)

Сущности легко сериализуются в стандартные словари Python (например, для JSON API, логирования или импорта/экспорта):

```python
# Экспорт в словарь (включая строки спецификаций)
data = order.to_dict()
# {
#     "id": 1,
#     "number": "SO-2026-00001",
#     "customer": 42,
#     "Items": [
#         {"product": 10, "quantity": 2, "price": Decimal("100.00"), "amount": Decimal("200.00")}
#     ]
# }

# Восстановление объекта из словаря
restored = SalesOrder.from_dict(data)
```

## 6. Многострочный текст и копирование записей

### Многострочный ввод: `multiline=True`
Для длинных описаний, заметок и инструкций дескриптор `String` поддерживает параметр `multiline=True`. Приложение автоматически создаст многострочный редактор `QPlainTextEdit` и выделит колонку типа `Text` в базе данных:

```python
class Task(MasterData):
    name = String(required=True)
    description = String(multiline=True) # Полноценное многострочное поле
    deadline = DateTime(required=True)
```

### Кнопка «Копировать» в списках (`ListView`)
В панели действий списков появилась стандартная кнопка **«Копировать»**. Она автоматически дублирует данные выбранной строки (включая строки спецификаций), сбрасывает первичный ключ и номер и открывает форму для подтверждения или редактирования нового объекта.

## 7. Сервис напоминаний о дедлайнах (`ReminderService`)

Для задач, заказов и целей с датой исполнения DECUI предоставляет встроенный сервис отслеживания сроков с интерактивным окном напоминаний:

```python
# Активация сервиса напоминаний в приложении
app.enable_reminders(
    [Task],
    date_field="deadline",
    done_field="is_completed",
    notify_before_minutes=60, # Предупреждать за 1 час до дедлайна
)
```

Диалог `ReminderDialog` позволяет:
- **Открыть задачу** в карточке редактирования;
- **Перенести срок** на новую дату/время с мгновенным сохранением в БД;
- **Отметить задачу выполненной** одним кликом;
- **Поздравить пользователя** при завершении цели через `celebrate_goal_completed("Цель достигнута. Отличная работа!")`.

## 8. Визуальная стилизация в списках и отчётах

- **В списках (`ListView`):** завершённые задачи автоматически отображаются зачёркнутым шрифтом и серым цветом (при `is_completed=True` или статусе «Завершена»).
- **В отчётах (`ReportView`):** возвращаемые строки могут содержать управляющие ключи форматирования:
  - `_style="completed"` — зачёркнутый серый шрифт;
  - `_style="current"` — полужирный шрифт для выделения текущего этапа;
  - `_color="#2563eb"` — произвольный цвет ячейки.

## 9. Утилиты для тестирования и Database Helpers

Для написания модульных тестов и фикстур добавлены методы быстрого создания БД и заполнения данных (seed):

```python
import pytest
from decui import Database

@pytest.fixture
def db():
    # Создание быстрой базы данных в памяти
    return Database.memory()

def test_sales_flow(db):
    # Пакетное сохранение тестовых данных
    products = db.seed([
        Product(name="Товар 1", unit_price=Decimal("100")),
        Product(name="Товар 2", unit_price=Decimal("200")),
    ])
    
    # Фильтрация
    found = db.filter(Product, name="Товар 1")
    assert len(found) == 1
```
