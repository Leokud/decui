# DECUI — Декларативный ERP-фреймворк для Python

[![Python](https://img.shields.io/badge/Python-3.12%2B-blue.svg)](https://www.python.org/)
[![PySide6](https://img.shields.io/badge/GUI-PySide6%20%28Qt6%29-green.svg)](https://wiki.qt.io/Qt_for_Python)
[![SQLAlchemy](https://img.shields.io/badge/ORM-SQLAlchemy%202.0%2B-red.svg)](https://www.sqlalchemy.org/)
[![Web Tutorial](https://img.shields.io/badge/Web_Tutorial-GitHub_Pages-blueviolet.svg)](https://leokud.github.io/decui/)

**DECUI** — это легковесный декларативный (metadata-driven) Python-фреймворк для создания настольных учетных и ERP-систем.

> 🌐 **Интерактивный веб-учебник:**  
> Пройдите пошаговый курс в браузере: **[leokud.github.io/decui](https://leokud.github.io/decui/)**


Вы описываете **только структуру данных и бизнес-логику в виде Python-классов** — фреймворк автоматически генерирует:
- Таблицы базы данных в SQLite и модели SQLAlchemy (с изоляцией на экземпляр `Database` и неразрушающим обновлением схемы)
- Оконные формы создания и редактирования с валидацией, вкладками и группами, а также декларативные и программируемые кастомные формы (`__form__ = Form(...)`, `@form_for`, `EntityForm`)
- Списки записей с поиском, отборами, сортировкой, CSV-импортом/экспортом и CRUD-операциями (`ListView`)
- Дерево навигации по разделам и модулям (`NavigationPanel`)
- Табличные части / спецификации с автокалькуляцией сумм (`@line_items`)
- Регистры накопления остатков и истории значений (`@ledger`, `@history_register`)
- Маршруты согласования (`Workflow`), локальные учётные записи с правами по ролям и печатные HTML/PDF-формы (`PrintForm`)
- Параметрические отчёты с группировками, вариантами, агрегацией, CSV-экспортом и диаграммами (`@report`)
- Понятные русскоязычные сообщения об ошибках БД на границе UI и сборку в единый файл `.exe` через PyInstaller

## Первое приложение

Из корня репозитория с Python 3.12+ и uv выполните команды. Они одинаковы в
Bash и PowerShell.

```bash
uv sync --locked --inexact
uv run --locked decui new warehouse --template basic
cd warehouse
uv run --locked decui run
```

В открывшемся списке «Товары» нажмите «Новый», введите название и цену и
сохраните карточку. Перезапустите приложение, чтобы увидеть сохранённый товар.
Нажмите `Ctrl+F`, чтобы найти товар. Если список пуст из-за условий поиска,
кнопка «Сбросить» очищает поисковую строку и отбор по полям.
В карточке `Ctrl+S` сохраняет правки. При выходе из изменённой карточки
можно сохранить правки, отказаться от них или продолжить редактирование.

Откройте `app.py`. Один класс `Product` описывает карточку, столбцы списка
и таблицу SQLite. Добавьте поле «Приоритет» по инструкции в быстром старте.
[Пошаговый урок](decui/docs/01-quickstart.md)

В каталоге `warehouse` команда `uv run --locked decui check` проверяет схему,
а `uv run --locked decui test -q` запускает прилагаемый тест сохранения товара.

### Пример с заказами

Вернитесь в корень репозитория. Шаблон `orders` добавляет клиентов, заказы,
строки заказа, отчёт и тест проведения.

```bash
uv run --locked decui new my_orders --template orders
cd my_orders
uv run --locked decui run
```

В отчёте одна выборка загружает заказы за указанные календарные дни вместе
со строками, из которых вычисляются суммы. [Урок по отчётам](decui/docs/05-reports.md#отчёт-по-строкам-за-период)

Отчёт «Закупки по строкам» открывается из карточки поставщика с заполненным
фильтром. [Упражнение с закупками](decui/docs/01-quickstart.md#упражнение-с-заказами-и-отчётом)

После изменения фильтров нажмите «Сформировать» или `F5`. Пока отчёт
показывает результат с прежними параметрами, экспорт CSV недоступен.

## 🎯 Для кого этот фреймворк?

- **Python-разработчикам:** Вам нужно быстро сделать рабочее настольное приложение для учета заказов, склада, клиентов или финансов? Не нужно вручную верстать виджеты Qt, писать SQL-запросы или связывать сигналы форм — фреймворк сделает это сам.
- **Разработчикам 1С и ERP-систем:** Вы найдете знакомые и проверенные концепции (справочники, документы, движения, регистры, проведение), но написанные на чистом, типизированном Python с поддержкой современных библиотек, Git и тестов.

## 📚 Терминология: Общепринятые понятия vs 1С

DECUI предоставляет удобные синонимы. Вы можете писать код в терминах классического бэкенда/ERP или в привычных терминах 1С:

| Общепринятый термин (ERP / Backend) | Термин 1С | DECUI API | Назначение |
|---|---|---|---|
| **Master Data / Lookup** | Справочник | `Catalog` / `MasterData`, `@catalog` / `@master_data` | Списки условно-постоянных объектов (товары, клиенты) |
| **Transaction / Document** | Документ | `Document` / `Transaction`, `@document` / `@transaction` | Хозяйственные операции, привязанные ко времени |
| **Line Items / Child Table** | Табличная часть | `@line_items` / `@tab_part` | Строки спецификаций внутри документа |
| **Form Action** | Команда | `@action` / `@command` | Кнопка на форме с привязанной бизнес-логикой |
| **Balance Ledger** | Регистр накопления | `@ledger` / `@accumulation` | Журнал учета остатков и оборотов (склад, касса) |
| **Value History** | Регистр сведений | `@history_register` / `@information` | Хранение параметров во времени (курсы валют, тарифы) |
| **Ledger Entry** | Движение | `LedgerEntry` / `Movement` | Единичная запись изменения баланса (`+` / `-`) |
| **Posting / Approval** | Проведение | `db.post(doc)`, `db.unpost(doc)`, `doc.is_posted` | Фиксация документа и создание записей в регистрах |
| **Sequence Numbering** | Автонумерация | `__numbering__ = {"prefix": "INV", ...}` | Генерация номеров по шаблону (`INV-2026-000001`) |
| **Navigation Section** | Подсистема | `__section__ = "Склад/Товары"` | Группировка в левом дереве навигации |
| **Report** | Отчёт | `Report` / `QueryReport`, `@report` | Экран параметрического отчёта с агрегацией и графиком |

> Подробное руководство по концепциям учета доступно в [docs/11-concepts-guide.md](decui/docs/11-concepts-guide.md).

## DECUI Studio

```bash
decui studio [app.py | project.decui.json]
```

**DECUI Studio** — визуальная IDE для создания и сопровождения приложений DECUI.
В пустом проекте нажмите «Открыть пример „Заказы и накладные“», «CRM и доставка» или «Закупки и прайс-листы»
и затем «Запустить», либо импортируйте существующий Python-файл (`app.py`) через «Импортировать из Python (app.py)…»
или передайте путь в CLI (`decui studio app.py`). Кнопка «Учебник» открывает пошаговое руководство в браузере.
В боковой панели можно искать объекты, добавлять готовые заготовки («Добавить из заготовки»),
дублировать объекты, менять их порядок, а при создании объекта или вводе русской подписи
имя Python подбирается автоматически (работают отмена и повтор изменений структуры).

### Конструктор форм (вкладка «Форма») и настройка без кода

- **Визуальный дизайнер форм:** на вкладке «Форма» можно включить `__form__ = Form(...)`, применить готовый шаблон компоновки (стандартный, двухколоночная шапка, компактный), перетаскивать/вкладывать строки (`FormRow`), колонки (`FormColumn`), сворачиваемые группы (`FormGroup`), вкладки (`FormTabs`/`FormTab`), поля (`FormField` с подсказкой `placeholder` и условием `visible_when`), табличные части (`FormTable`), кнопки команд (`FormButton`), заголовки (`FormLabel`) и разделители (`FormDivider`) с живым предпросмотром справа.
- **Программируемые хуки формы:** во встроенной подвкладке «Код формы (`EntityForm`)» описываются обработчики `on_open`, `on_field_changed`, `on_table_changed`, `on_before_save` и `build_extra` для класса `@form_for(Entity)`.
- **Действия без кода:** в окне «Кнопки действий…» кнопка **«Создать без кода…»** генерирует обработчики (изменение поля, проведение/снятие проведения, смена статуса согласования, обновление даты/счётчика) без ручного написания Python.
- **Расчёты, проверки и поля:** в карточке объекта доступны шаблон автонумерации (`{prefix}-{year}-{seq:05d}`), флаг контроля последовательности проведения (`__sequence__`), конструктор «Расчёты и проверки…» (`before_save` / `on_validate`), предпросмотр карточки («Предпросмотр формы»), дублирование полей, `placeholder` строк, пары `CODE: Label` в `Choice` и параметры ссылок `Ref`.

### Встроенная Python IDE на базе Pyrefly LSP

- **Анализ кода в реальном времени:** Studio автоматически запускает встроенный языковой сервер `pyrefly lsp` и проверяет весь проект вместе с локальной конфигурацией DECUI.
- **Диагностика, подсказки и навигация:** во всех редакторах Python («Код объекта», «Код формы», «Код перед/после объектов» и «Код проекта») работают волнистые подчёркивания ошибок, маркеры на полях, всплывающие подсказки типов (`hover`), сигнатуры функций (`Ctrl+Shift+Space`), умное автодополнение (`Ctrl+Space` включая `self.` и поля DECUI), переход к определению (`F12` / `Ctrl+клик`), парные скобки и автозакрытие кавычек/скобок.
- **Нижняя панель IDE и прямой режим `app.py`:** вкладки **«Проблемы»** и **«Символы кода»** позволяют мгновенно переходить к нужной строке любого объекта; на вкладке **«Код проекта»** флажок **«Редактировать app.py напрямую (LSP IDE)»** открывает полный код для правки и синхронизирует его обратно в визуальную структуру кнопкой **«Применить код в Studio»**.

В карточке объекта нажмите «Добавить таблицу». Выберите таблицу
в списке над полями и добавьте колонки, в том числе ссылки на справочники.
На вкладке «Регистры» можно описать регистры накопления и сведений
(включая `representation_field` для измерений-ссылок), дублировать и переставлять их. Шаблон «Товары и накладные» показывает проведение
накладной с движениями и отчёт остатков, а «Закупки и прайс-листы» — срез последних цен поставщиков. Выберите документ и откройте
вкладку «Движения». Выберите регистр, приход или расход (или поле даты для сведений), запись на документ
или на строку таблицы, затем сопоставьте поля. Для особых правил можно
описать движения методом `get_movements()` в Python.

На вкладке «Отчёты» можно выбрать объект (включая отчёты по строкам табличной части),
или регистр, колонки, сортировку, фильтр по периоду, срез последних (`latest_only`),
признак проведённого документа, быстрый отбор по тексту и выбору,
отбор по ссылке (включая `from_record` для запуска из карточки), раздел меню,
встроенную столбчатую диаграмму (`chart`), условное оформление строк и индивидуальное форматирование колонок,
а кнопка «Предпросмотр» открывает результат отчёта сразу в Studio.
Для регистра накопления выбранные измерения группируют остатки. Для регистра
сведений выводится история записей или срез последних.

На вкладке «Начальные данные» записи можно загрузить прямо из заполненной SQLite-базы («Загрузить из базы…»).
На вкладке «Приложение» задаются стартовый экран, размер окна, напоминания о
сроках (`enable_reminders`), обзор всех ролей проекта и файл рабочей базы.
Вкладка «Обзор» показывает дерево разделов, интерактивную ER-схему связей с экспортом в PNG и мгновенную
диагностику проекта с переходом к проблемному месту.

Через меню «Действия» можно импортировать Python-проект, запускать приложение с постоянной рабочей базой,
открывать встроенный «Инспектор базы данных» (просмотр таблиц SQLite, экспорт в CSV и SQL-запросы только для чтения),
запускать сгенерированный автотест проекта («Запустить автотест проекта»),
проверять миграцию на рабочей базе или копии, экспортировать `app.py` или
полный проект (`app.py`, `test_app.py`, `README.md`, `.gitignore`), сохранять
резервные копии и открывать недавние проекты.
В редакторе поля укажите «Группа на форме». Поля с одинаковым названием
появятся в одном блоке при предпросмотре и в собранном приложении.
Пустое значение оставляет поле в основной части формы. В Python тот же
параметр задаётся в классе объекта, например `__form_groups__ = {"price": "Стоимость"}`.
Поле «Вкладка на форме» переносит поле вместе с его группой на указанную
вкладку. Аналог в Python — `__form_tabs__ = {"price": "Учёт"}`. Поля без
вкладки остаются над вкладками.

Чтобы получить вложенные подытоги, отметьте поля в «Порядке группировок»
и перетащите их в нужном порядке. Группы и общий итог попадут и в CSV.
Нажмите «Шаблоны → Цели и задачи», чтобы открыть готовый проект со связанными задачами,
проверкой сроков, отчётом и напоминаниями. «Проверить» проверяет модели и
схему SQLite. При ошибке Python кнопка «К строке ошибки» открывает
нужное место в редакторе или в коде последнего запуска.
«Запустить» открывает приложение с временной базой для предпросмотра.

Во вкладке «Согласование» можно задать статусы, начальный статус и
допустимые переходы. Для документов можно ограничить проведение
выбранными статусами. Посмотрите пример «Шаблоны → Согласование
накладных». Приложение показывает доступные действия в карточке
сохранённого документа, а база проверяет переходы при сохранении.
Кнопка «История» показывает время, действие и статусы до и после перехода.
В колонке «Роли через запятую» можно ограничить каждый переход. Приложение
задаёт роль контекста через `set_role("manager")`. DECUI применяет её к
действиям в карточке и к изменениям статуса через API. Пустой список ролей
допускает любой контекст. Кнопка «История» показывает и роль, действовавшую
при переходе. Из Python журнал доступен через `db.workflow_history(entity)`.
Для проверки используйте «Роль предпросмотра» на вкладке «Приложение».
Эта настройка действует только в Studio. Чтобы требовать вход в
экспортированном приложении, включите «Требовать вход в приложение».
При первом запуске создаётся администратор, затем через меню «Учётные
записи» он может добавить локальных пользователей и назначить им роли.
Роль выбирается по учётной записи после входа. База и приложение должны
работать под доверенной учётной записью ОС: прямой доступ к файлу SQLite
позволяет менять локальные данные.

Чтобы переход мог выполнить только конкретный пользователь, отметьте
«По назначению» в маршруте. В приложении с учётными записями администратор
выбирает согласующего в сохранённой карточке. Исполнитель должен совпасть
с назначенным логином и иметь подходящую роль. История показывает логин
автора перехода и смену согласующего.

Для справочника или документа можно включить «Только владелец и
администратор». Владельцем новой записи становится вошедший пользователь.
Списки, отчёты на базе API и операции с записями используют это ограничение.
Назначенный согласующий может открыть запись, прочитать её историю и
выполнить назначенный переход. Сохранение реквизитов, проведение, удаление
и изменение движений доступны владельцу и администратору. Для ранее
сохранённых записей без владельца сохраняется доступ администратора.
Предпросмотр проектов с правами по владельцу или назначению требует входа.

Кнопка «Настроить права по ролям» открывает матрицу операций объекта.
Отметьте чтение и отдельно разрешённые операции создания, изменения,
удаления и проведения. Матрица дополняет доступ по владельцу и требует
входа в приложение.

Для реквизита или колонки табличной части можно включить «Ограничить изменение по ролям».
Пустой список означает, что поле меняет администратор. Остальные
пользователи могут видеть его значение. При создании записи поле
получает значение по умолчанию. Настройка действует в карточке и в API
при сохранении; пользовательский код в обработчиках сохранения может
вычислять служебные поля. В новых строках защищённая колонка получает
значение по умолчанию. Удалять строки из таблицы можно при наличии
доступа на изменение всех её защищённых колонок.

«Ограничить чтение по ролям» скрывает реквизит или колонку от остальных
ролей. Значение не возвращается через API, а фильтрация и сортировка по
закрытому реквизиту отклоняются. При сохранении других полей исходное
значение остаётся в базе. Для пользователя со скрытыми полями документа
проведение и движения такого документа недоступны.

В документе можно выбрать «Настроить печатную форму» и отметить
реквизиты и колонки табличных частей. Для сохранённого документа
кнопка «Печатная форма» открывает просмотр и экспорт PDF. В шаблоне
«Товары и накладные» форма уже настроена. Печать учитывает права на
чтение полей и использует данные из базы.

В готовом приложении команда «Данные → Сохранить резервную копию»
создаёт отдельный файл SQLite. В приложении с учётными записями команда
доступна администратору. В Studio откройте проект этого приложения и
выберите «Действия → Запустить с копией». Изменения в тестовом запуске попадают
во временную базу. Если в резервной копии есть учётные записи, вход
выполняется с ними.

На вкладке «Начальные данные» можно подготовить записи справочников,
документы и строки табличных частей. Для ссылки укажите ключ другой
начальной записи. Studio расставит записи в порядке зависимостей.
На первом запуске новой базы данные сохраняются одной транзакцией.
В шаблоне «Товары и накладные» уже есть товары и черновик накладной.

Сохраните исходный проект как `*.decui.json`. «Действия → Экспорт Python» создаёт
`app.py` в выбранной папке. В экспортированном приложении данные
сохраняются в локальном хранилище по идентификатору приложения.
Команда «Действия → Собрать» создаёт исполняемый файл для текущей платформы, а журнал
показывает вывод PyInstaller. Для Windows запускайте сборку на Windows.
В сборку входят настройки экспортированного проекта, а временная база и
роль предпросмотра остаются в Studio. Существующий файл сборки сохраняется.
Из терминала запустите экспортированный файл через `decui run app.py`.
Для сборки из терминала см. [руководство по сборке](decui/docs/07-building.md).

Вкладка «Объект» принимает Python-код методов класса и команд. На вкладке «Приложение» можно добавить импорты перед объектами,
отчёты и регистры после объектов, а также функцию `configure_app(app)`
для настройки перед запуском. Изменения в экспортированном Python-файле
живут в этом файле. Чтобы продолжить работу в студии, редактируйте
исходный проект.

## Пример «Цель. Код будущего»

```bash
uv run --locked python -m examples.future_goals
```

Пример создаёт пять демонстрационных целей при первом запуске. В карточке
сохранённой цели можно добавлять и редактировать задачи, проверять их сроки
и видеть прогресс. Отчёт «Динамика достижения целей» показывает этапы
активных целей. Напоминания появляются за час до срока, пока приложение
открыто. База SQLite хранится в локальном каталоге данных пользователя.

Для сборки офлайн-версии выполните на целевой платформе:

```bash
python -m PyInstaller --onefile --windowed --name FutureGoals --paths . --collect-all sqlalchemy examples/future_goals.py
```

На Windows результат появится в `dist/FutureGoals.exe`.

## 🛠 Пример с транзакциями, строками и регистрами

```python
from decimal import Decimal
from decui import (
    ERPApplication, MasterData, Transaction, String, Integer, Decimal as D, Ref,
    master_data, transaction, line_items, action, ledger, Ledger, Dimension, Metric, LedgerEntry
)

# 1. Справочник товаров
@master_data
class Item(MasterData):
    name = String("Товар", required=True)
    price = D("Цена", precision=10, scale=2, default=Decimal("0.00"))

# 2. Регистр остатков склада
@ledger
class StockLedger(Ledger):
    product = Dimension("Товар")
    qty = Metric("Количество")

# 3. Документ продажи
@transaction
class SaleOrder(Transaction):
    __verbose_name__ = "Заказы покупателей"
    __section__ = "Продажи"

    customer = String("Покупатель", required=True)
    total = D("Итого", precision=10, scale=2, read_only=True, default=Decimal("0.00"))

    # Табличная часть со строками заказа
    @line_items
    class Items:
        product  = Ref(Item, "Товар", representation_field="name")
        quantity = Integer("Кол-во", default=1, min_value=1)
        price    = D("Цена", precision=10, scale=2)
        amount   = D("Сумма", precision=10, scale=2, read_only=True)

    # Кнопка пересчета суммы на форме
    @action("Пересчитать")
    def calc(self):
        self.total = sum(
            Decimal(str(r.get("quantity", 1))) * Decimal(str(r.get("price", 0)))
            for r in self.Items
        )

    # Движения по складу при проведении заказа (списание товара)
    def get_ledger_entries(self):
        return [
            LedgerEntry(
                register=StockLedger,
                dimensions={"product": row["product"]},
                resources={"qty": row["quantity"]},
                is_income=False,  # списание со склада
            )
            for row in self.Items
        ]
```

## 🚀 CLI-утилита `decui` и эргономика (DX)

Команды `decui run`, `decui check` и `decui build` ищут `app.py`, затем
`main.py`. Другую точку входа можно указать явно, например `decui run orders.py`.
Команды также доступны через `python -m decui.cli`.
Если ссылочная модель не зарегистрирована, `decui check` показывает её имя
и путь к месту использования, например `SalesOrder.Items.product`.
Команда `decui test` передаёт параметры pytest. Например, `decui test -q test_app.py`
запускает тест шаблона с кратким выводом.

### Ключевые возможности DX:
- **Авто-названия полей (Auto-naming):** `name = String(required=True)` вместо дублирования `String("Name")`.
- **Коллекция спецификаций:** `doc.Items.add(...)` и `doc.Items.total("amount")` без ручных циклов.
- **Active Record:** `product.save(db)`, `product.delete(db)`, `Customer.filter(db, is_active=True)`.
- **Сериализация:** `entity.to_dict()` и `Entity.from_dict(data)` для легкого обмена данными.
- **Тестовые хелперы:** `Database.memory()` и `db.seed([e1, e2])`.

> Подробное описание всех возможностей доступно в [docs/12-dx-guide.md](decui/docs/12-dx-guide.md).

## 📦 Сборка в автономный .exe

В активном окружении DECUI запустите `decui build app.py` из каталога
приложения. CLI сам передаст PyInstaller путь к DECUI. Результат появится
в `dist/app.exe` на Windows или `dist/app` на Linux.
См. [руководство по сборке](decui/docs/07-building.md#сборка-своего-приложения).

Из корня репозитория команда `uv run --locked python build_exe.py` собирает
демо `examples/simple.py` в `dist/ERP.exe` или `dist/ERP`. См.
[параметры сборки и проверку миграции](decui/docs/07-building.md).
